beloven, en zevren.nl noemt nergens een aantal weken. De FAQ zegt letterlijk:
"De doorlooptijd hangt af van het project. We geven je een duidelijke

week 3" erin zou dus een belofte doen die de site niet dekt, en dat is precies
de regel uit `CLAUDE.md`. Het artikel loopt daarom de vier fases langs die
wél op de site staan, en behandelt eerlijk waarom er geen getal bij staat.
Dat is bovendien het sterkere stuk: elk bureau kan "vier tot zes weken"
roepen, en niemand kan uitleggen waarom hij het niet weet.

## Engels

**title**

```
How long does a website actually take?
```

**excerpt**

```
Every agency has an answer ready and almost none of them can explain it. Here is what actually sets the clock on a website project, which parts you control, and why we will not name a number before we know what we are building.
```

**blocks**

`p`

```
After the price, this is the question everyone asks first. You want a number: three weeks, six weeks, something you can plan an opening or a campaign around. The honest answer is that anyone who gives you that number before seeing your project is guessing, and the guess is usually the one that sounds good in a sales conversation.
```

`p`

```
That is not a reason to accept "it depends" either. The timeline is not random. It follows a small number of things, most of which you can see in advance, and several of which are entirely in your hands. Here is what actually moves it.
```

`h2`

```
Why nobody can give you a date up front
```

`p`

```
A website is not a product on a shelf. Two businesses can ask for "a simple site with five pages" and mean completely different things: one has its texts, its photos and its prices ready, the other has a logo and an idea. The build is nearly identical. The project is not.
```

`p`

```
This is why we do not put a delivery time on our website. We give you an estimate before development starts, once we know what the site has to do and what content exists. An estimate given before that point is not information, it is a sales technique.
```

`h2`

```
The four stages, and where the time actually goes
```

`p`

```
Every project we run has the same four stages. What differs is how long each one takes, and it is almost never the one you expect.
```

`ul`

```
Discovery. We work out what the site has to achieve, which pages are genuinely needed and what content goes on them. This is the cheapest stage to change your mind in, and the one people most want to skip.
```

```
Design. You see the real structure with your own content in it, not placeholder text. This is where the clock most often stops, because your own content has to exist for this stage to finish.
```

```
Development. The design becomes a working site: responsive, fast, and written so it can be extended later. This is the most predictable stage in the whole project.
```

```
Launch. Forms, links, speed, search visibility and analytics get checked, then it goes live and you get what you need to run it.
```

`p`

```
Notice which stage is predictable. Development is the part that looks like the hard work, and it is the part we can estimate most accurately. The stages that stretch are the ones that depend on decisions and on content, and both of those sit largely with you.
```

`h2`

```
What actually holds a project up
```

`p`

```
In practice, the delays are rarely technical. They are the text that still has to be written, the photos that still have to be taken, the one page that turns out halfway through to need prices on it as well, and the decision that has to wait because the person who makes it is on holiday.
```

`p`

```
None of this is a complaint about clients. It is the normal shape of a project, and it is exactly why the discovery stage exists. A scope agreed at the start costs nothing to change. The same change three weeks later costs a redesign.
```

`h2`

```
What you can do this week to make it faster
```

`p`

```
If you want the clock to run short, most of the useful work can be done before you have chosen anyone at all.
```

`ul`

```
Write down every service you offer and what it costs. If you cannot put a price on it, note how you want to handle that, because the page will ask.
```

```
Collect the photos you genuinely like. Not the ones that will do, the ones you would put on a poster. Weak photos are the single most common reason a finished site looks cheaper than it is.
```

```
Decide what a visitor must be able to do: call, book, order, or simply find your address and opening hours. One primary action per page is enough.
```

```
Find out who controls your domain name, and get access before you need it. This is a favourite source of last-minute delay and it has nothing to do with building anything.
```

`h2`

```
What a "fast" website usually means
```

`p`

```
Some agencies will promise you a live site in a week. That is achievable, and it is worth knowing what makes it possible: a template, your logo dropped in, and your text poured into a layout designed for someone else. There is nothing dishonest about it, as long as it is what you wanted. It becomes a problem when you later want something the template cannot do.
```

`p`

```
The middle road, and the one most small businesses should be on, is a site designed around your content but built without ceremony. That is not measured in weeks up front. It is measured by how quickly the two of you can answer the questions the site asks.
```

`p`

```
Our prices are published for the same reason we will not publish a delivery time we cannot keep: a starter website is 299 euros, a full business website 549, an online store 899, and custom web applications start at 1,349. You will have your estimate before development starts, and the reasoning behind it.
```

## Nederlands

**title**

```
Hoe lang duurt het maken van een website?
```

**excerpt**

```
Elk bureau heeft er een antwoord op klaarliggen en bijna geen enkel bureau kan het uitleggen. Dit is wat de klok van een websiteproject echt bepaalt, welk deel daarvan bij u ligt, en waarom wij geen getal noemen voordat we weten wat we bouwen.
```

**blocks**

`p`

```
Na de prijs is dit de vraag die iedereen als eerste stelt. U wilt een getal: drie weken, zes weken, iets waar u een opening of een campagne omheen kunt plannen. Het eerlijke antwoord is dat wie u dat getal geeft voordat hij uw project gezien heeft, aan het gokken is. En die gok valt meestal net zo uit als het in een verkoopgesprek goed klinkt.
```

`p`

```
Dat betekent niet dat u genoegen moet nemen met "dat hangt ervan af". De doorlooptijd is niet willekeurig. Hij volgt uit een handvol dingen die u grotendeels vooraf kunt zien, en waarvan een flink deel in uw eigen handen ligt. Dit is wat hem echt beweegt.
```

`h2`

```
Waarom niemand u vooraf een datum kan geven
```

`p`

```
Een website is geen product uit een schap. Twee bedrijven kunnen allebei vragen om "een eenvoudige site met vijf pagina's" en daar iets compleet anders mee bedoelen: de een heeft zijn teksten, zijn foto's en zijn prijzen klaarliggen, de ander heeft een logo en een idee. Het bouwwerk is bijna hetzelfde. Het project niet.
```

`p`

```
Daarom staat er op onze site geen levertijd. U krijgt een inschatting voordat de ontwikkeling begint, op het moment dat duidelijk is wat de site moet doen en welke content er al is. Een inschatting die eerder wordt gegeven, is geen informatie maar een verkooptechniek.
```

`h2`

```
De vier stappen, en waar de tijd echt in gaat
```

`p`

```
Elk project dat wij doen kent dezelfde vier stappen. Wat verschilt is hoe lang elke stap duurt, en dat is bijna nooit de stap die u verwacht.
```

`ul`

```
Discovery. We bepalen wat de site moet bereiken, welke pagina's echt nodig zijn en wat daarop komt te staan. Dit is de goedkoopste plek om nog van gedachten te veranderen, en de stap die mensen het liefst overslaan.
```

```
Design. U ziet de echte opbouw met uw eigen content erin, geen placeholdertekst. Hier staat de klok het vaakst stil, want uw content moet bestaan voordat deze stap af kan zijn.
```

```
Development. Het ontwerp wordt een werkende site: responsive, snel, en zo geschreven dat hij later uit te breiden is. Dit is de best voorspelbare stap van het hele project.
```

```
Launch. Formulieren, links, snelheid, vindbaarheid en statistieken worden gecontroleerd, daarna gaat hij live en krijgt u wat u nodig heeft om hem draaiende te houden.
```

`p`

```
Let op welke stap voorspelbaar is. Development lijkt het zware werk en is juist het deel dat wij het nauwkeurigst kunnen inschatten. De stappen die uitlopen zijn de stappen die afhangen van beslissingen en van content, en die liggen allebei grotendeels bij u.
```

`h2`

```
Waar een project in de praktijk op blijft liggen
```

`p`

```
De vertraging is zelden technisch. Het zijn de teksten die nog geschreven moeten worden, de foto's die nog gemaakt moeten worden, de ene pagina waarvan halverwege blijkt dat er ook nog prijzen op moeten, en de beslissing die moet wachten omdat degene die hem neemt op vakantie is.
```

`p`

```
Dat is geen klacht over klanten. Zo ziet een project er nu eenmaal uit, en het is precies de reden dat de eerste stap bestaat. Een omvang die u aan het begin afspreekt, kost niets om te veranderen. Dezelfde verandering drie weken later kost een nieuw ontwerp.
```

`h2`

```
Wat u deze week al kunt doen om het sneller te laten gaan
```

`p`

```
Wilt u dat de klok kort loopt, dan kan het meeste nuttige werk gedaan worden voordat u überhaupt iemand gekozen heeft.
```

`ul`

```
Schrijf op welke diensten u aanbiedt en wat ze kosten. Kunt u er geen prijs op zetten, noteer dan hoe u dat wilt oplossen, want de pagina gaat er toch om vragen.
```

```
Verzamel de foto's die u echt goed vindt. Niet de foto's die er nog wel mee door kunnen, maar de foto's die u op een poster zou zetten. Zwakke foto's zijn de meest voorkomende reden dat een afgeronde site er goedkoper uitziet dan hij is.
```

```
Bepaal wat een bezoeker moet kunnen doen: bellen, boeken, bestellen, of gewoon uw adres en uw openingstijden vinden. Eén hoofdactie per pagina is genoeg.
```

```
Zoek uit wie uw domeinnaam beheert en regel de toegang voordat u hem nodig heeft. Dit is een klassieke bron van vertraging op het laatste moment, en het heeft niets met bouwen te maken.
```

`h2`

```
Wat een "snelle" website meestal betekent
```

`p`

```
Sommige bureaus beloven u binnen een week een site die live staat. Dat kan echt, en het is nuttig om te weten wat het mogelijk maakt: een template, uw logo erin, en uw tekst gegoten in een opzet die voor iemand anders is ontworpen. Daar is niets oneerlijks aan, zolang het is wat u wilde. Het wordt pas een probleem als u er later iets van wilt wat de template niet kan.
```

`p`

```
De middenweg, en de weg waar de meeste kleine bedrijven op horen, is een site die om uw content heen is ontworpen en zonder omhaal gebouwd. Die laat zich vooraf niet in weken uitdrukken. Hij laat zich uitdrukken in hoe snel u en de bouwer samen de vragen kunnen beantwoorden die de site stelt.
```

`p`

```
Onze prijzen staan openbaar om dezelfde reden dat wij geen levertijd publiceren die we niet kunnen waarmaken: een starterwebsite kost 299 euro, een volledige bedrijfssite 549, een webshop 899, en maatwerk webapplicaties beginnen bij 1.349. Uw inschatting krijgt u voordat de ontwikkeling begint, met de redenering erbij.
```

## Controles die ik gedaan heb

- **Elke claim tegen zevren.nl.** De vier stappen en hun beschrijvingen komen
  uit `process.steps` in de dictionaries (Discovery, Design, Development,
  Launch), inclusief "de echte opbouw met uw eigen content, geen placeholder"
  en "hier wordt de omvang bepaald". De zin over de inschatting komt uit het
  FAQ-item "Hoe lang duurt een website?". De prijzen komen uit `PLANS` in
  `zevren/lib/offer.ts`.
- **Geen levertijd beloofd.** Nergens in beide teksten staat een aantal
  weken of dagen als toezegging. De enige keer dat er een termijn valt ("een
  week") gaat het over wat ánderen aanbieden, met de uitleg erbij.
- **Geen verzonnen aantallen, klanten of resultaten.** Er staat geen enkel
  cijfer in het artikel behalve de vier openbare prijzen en het aantal
  stappen.
- **Geen schaarste, geen "wij zijn klein", geen uitroeptekens, geen em
  dashes.**
- **Geen van de drie verboden formuleringen** uit
  `.agents/product-marketing.md`: gezocht op `aanklikken`, `een foto van` en
  `eigen naam`, nul treffers.
- **Register.** Nederlands consequent "u", passend bij het publiek van dit
  artikel (ondernemers die een investering overwegen).
